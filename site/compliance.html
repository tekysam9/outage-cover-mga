Controls you can audit

Hash-chained audit log

Every action is chained to the one before it. Any edit is detected on verification.

Decision replay

Stored inputs re-run through the versioned rules and must match the original result.

Two-person rate changes

A rate change needs a proposer and a different approver. Old policies keep their rates.

Approval limits

Payouts above $15,000 need approval. Area exposure above $100,000 per ZIP is referred to underwriting.

Role-based access

Merchants, partners, underwriting, operations, auditors and admins each see only what they need.

Bordereau reporting

Policy and paid-loss data exports for the carrier and reinsurers.

Status. Prototype. Real operation needs a fronting carrier, state licensing or an MGA appointment, counsel review in each state and a real payments provider. This build uses a mock payment provider and placeholder rates.
